# Mobile GUI

This is the first small-screen-first scaffold for the file synchronization engine mobile clients. It locks shared Android and iOS UI/runtime contracts before platform-specific app shells are built.

## Contract

- Android and iOS clients remain separate GUI applications that control the engine through the local encrypted API or a remote encrypted API; UI code must not import daemon internals.
- The navigation model starts with mobile-sized views for overview, folders, peers/identity, transfers, warnings/logs, maintenance/backups, daemon settings, mobile app settings, and help/details.
- The remote instance management contract follows the desktop model: local engine first when present, direct endpoint onboarding, pairing/import flows, and identity-linked remote hosts.
- The identity pairing import/export contract must include copyable text, shareable identity files, pasted/imported packages, and an animated pairing scanner with progress before the payload is accepted.
- Mobile pairing entrypoints must expose copyable text, a shareable identity file/download, platform share-sheet payloads, a QR fallback, pasted pairing code, uploaded identity file import, scanned animated-code import, and shared identity file import. Android stores imported pairing material through Android Keystore-backed secure storage, iOS stores it through iOS Keychain, and both paths must use secure local storage after successful import while keeping daemon-owned import execution behind the encrypted API.
- The platform secure credential storage boundary is required for daemon API credentials and identity material. The app registry may keep redacted metadata and credential references only.
- The mobile remote instance onboarding contract in `src/app/mobileRemoteInstances.ts` supports direct API endpoint/key, pasted pairing code, uploaded identity file, scanned animated pairing code, and shared identity file sources. Android stores remote credentials through Android Keystore and iOS stores them through iOS Keychain; app state keeps only `credentialRef`, endpoint, peer ID/code, and redacted progressive status. Loaded shared identity snapshots perform automatic same-identity instance population and progressively hydrates status, folders, capabilities, and rates as encrypted discovery/negotiation completes.
- The mobile identity mesh relay checkpoint is `src/app/mobileMeshRelay.ts`: identity-linked mesh relay status means unreachable instances can be inspected or configured through reachable identity peers when direct encrypted API access is unavailable. Mobile settings edits use durable pending settings changes, eventually consistent delivery, authentication, authorization, owner-side validation, and visible `pending/applied/failed/acknowledged` status instead of pretending relayed edits are immediate.
- A cellular sync disable setting is part of the core mobile contract; transfers must check platform network state before starting mobile/cellular work.
- The degraded sync status surface must be visible whenever permissions, power state, platform background limits, network state, or policy prevent continuous daemon-style operation.
- The first mobile daemon API client wires folders, peers, discovery, transfers, warnings/logs, maintenance, backups, and settings screens to the authenticated daemon API while keeping credential references only in UI state; platform secure storage resolves API keys at call time. `src/app/mobileScreens.ts` maps the operational screen IDs to the shared API client loaders/commands so platform shells can bind screens without importing daemon internals or storing credential material.
- Android shell contract: `src/android/androidShell.ts` defines the first small-screen navigation shell state for the Android client. It keeps selected-host navigation, local encrypted API-only control, Android Keystore credential storage, foreground service and WorkManager requirements, battery optimization exemption prompts, notification permission state, cellular sync disable policy, and degraded background-sync status visible before native Android packaging exists.
- iOS shell contract: `src/ios/iosShell.ts` defines the first small-screen navigation shell state for the iOS client. It keeps selected-host navigation, local encrypted API-only control, iOS Keychain credential storage, iOS background tasks and background URLSession requirements, silent-push wake support status, short wake windows with checkpointing, cellular sync disable policy, and degraded background-sync status visible before native iOS packaging exists.
- The mobile animated pairing scanner checkpoint is `src/app/mobileAnimatedPairingScanner.ts`: it models frame de-duplication/reordering, collected frame count versus total frame count, clear progress text (`Keep phone pointed at screen until pairing is complete.`), complete-payload verification before daemon-owned import, and secure local storage after verified import through Android Keystore or iOS Keychain targets.
- Android animated pairing camera checkpoint: `src/android/androidShell.ts` now models the native camera permission and camera preview state for animated pairing, counts decoded/rejected frames, and feeds decoded animated frames into the shared scanner state while preserving the same progress guidance (`Keep phone pointed at screen until pairing is complete.`). The contract still requires complete-payload verification and Android Keystore storage after accepted import.
- Android background sync scheduler checkpoint: `src/android/androidShell.ts` now models Android-compliant scheduling decisions before native packaging exists. Active folder sync maps to a foreground service for active sync with a user-visible notification, deferred metadata catch-up, small pending transfers, scrub/repair checks, and retry work map to WorkManager for deferred metadata catch-up, small pending transfers, scrub/repair checks, and retry work, the cellular sync disable policy blocks mobile network work before scheduling, battery/notification limitations surface degraded status, and every scheduled/background decision marks durable checkpoints before background work yields.
- Android battery optimization exemption checkpoint: `src/android/androidShell.ts` now models the user-facing exemption prompt for reliable background work: request battery optimization exemption only when continuous/background sync is enabled, explain that Android may pause sync while the app is idle unless exemption is granted, route the native request through Android's ignore-battery-optimizations settings action, and surface degraded status if the OS refuses or the user declines.
- iOS animated pairing camera checkpoint: `src/ios/iosShell.ts` now models iOS camera authorization and the AVFoundation capture session state for animated pairing, counts decoded/rejected frames, and feeds decoded animated frames into the shared scanner state while preserving the same progress guidance (`Keep phone pointed at screen until pairing is complete.`). The contract still requires complete-payload verification and iOS Keychain storage after accepted import.
- iOS background sync scheduler checkpoint: `src/ios/iosShell.ts` now models iOS-compliant scheduling decisions around documented wake/work opportunities. Metadata catch-up, small pending transfers, resumable block chunks, checkpoint flushes, and retry work choose among background app refresh, background tasks, background URLSession, silent push wakeups, or foreground-only work without non-public APIs. Short wake windows prioritize metadata catch-up, small pending transfers, resumable block chunks, and durable checkpoint flushes through an explicit ordered execution plan with remaining wake budget, an early exit deadline, durable checkpoint-before-exit, quick-exit, and reschedule the next permitted wake before suspension requirements; cellular policy can block mobile-network work before scheduling.
- The mobile animated pairing scanner UI checkpoint is `src/app/mobileAnimatedPairingScannerScreen.ts`: Android and iOS shell states now bind a shared scanner screen model that presents collected/required/total frame progress, missing-frame details, duplicate-frame counts, secure-storage target, camera-permission/error states, and a clear `Pairing is complete` completion message while connectivity and authorization work continues silently in the background.
- The mobile degraded sync status checkpoint is `src/app/mobileDegradedStatus.ts`: Android and iOS shell states now bind a shared visible status model that explains when iOS policy, battery state, user settings, notification permission, network state, or background refresh restrictions mean continuous daemon-style syncing is degraded, with per-reason action-required flags instead of hiding platform limits.
- The mobile cellular sync setting checkpoint is `src/app/mobileSyncSettings.ts`: users can disable synchronization on mobile/cellular networks, Android and iOS network capability/state checks make cellular work blocked before scheduling, and Wi-Fi and Ethernet remain allowed when available.
- The mobile permissions checkpoint is `src/app/mobilePermissions.ts`: Android and iOS permission request/status planning covers storage/network/location/notification/background permissions based on configured sync options, including location permission when required to detect Wi-Fi/network state. This permission planner is a request/status contract, not a native entitlement implementation; platform shells surface the plan so native packaging can request only the permissions needed by enabled features.

## Boundaries

This scaffold is not a completed Android or iOS implementation. Native foreground-service, WorkManager, background-task, background URLSession, notification, Keychain/Keystore, platform package wiring, and native rendering of the bound screen models remain follow-on slices.
